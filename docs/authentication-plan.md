# Аутентификация пользователей на FastAPI

## Summary

Добавить FastAPI-бэкенд с PostgreSQL в Docker Compose: регистрация по `email`, имени и паролю, вход, обновление access JWT через одноразовый refresh-токен и logout. Регистрация сразу создаёт авторизованную сессию.

## Implementation Changes

- Подключить FastAPI, SQLAlchemy, Alembic, PostgreSQL-драйвер, безопасное хеширование паролей и JWT-библиотеку; создать приложение, маршруты и healthcheck.
- Добавить `User` (уникальный нормализованный email, имя, хеш пароля, даты создания) и `RefreshSession` (идентификатор JWT, пользователь, срок действия, отозвана ли сессия) с миграциями PostgreSQL.
- Реализовать `POST /api/v1/auth/register`, `POST /api/v1/auth/login`, `POST /api/v1/auth/refresh` и `POST /api/v1/auth/logout`.
- В `register` и `login` возвращать JSON с короткоживущим access JWT и данными пользователя; refresh JWT выдавать только в `HttpOnly`, `Secure`, `SameSite=Lax` cookie.
- На refresh проверять подпись, тип токена, срок действия и активность серверной сессии; отзывать старую сессию, создавать новую и возвращать новый access JWT вместе с заменённой cookie.
- На logout отзывать сессию из cookie и очищать cookie. Пароли никогда не возвращать и не хранить в исходном виде.
- Добавить `.env.example`, конфигурацию секретов/TTL/DB URL и `docker-compose.yml` для PostgreSQL и backend-сервиса. Docker-том сохраняет данные БД между перезапусками.

## Test Plan

- Регистрация создаёт пользователя, хеширует пароль, запрещает повторный email и выдаёт рабочую пару токенов.
- Login принимает корректные данные и отклоняет неверный email/пароль.
- Refresh выдаёт новый access и refresh, а повторное применение старого refresh отклоняется.
- Просроченные, поддельные, неверного типа и отозванные токены отклоняются.
- Logout делает текущий refresh недействительным и очищает cookie.
- Миграции применяются к чистой PostgreSQL БД; endpoint healthcheck доступен в Compose.

## Assumptions

- Email не подтверждается и восстановление пароля не входит в задачу.
- Пароль: минимум 8 символов; access JWT живёт 15 минут, refresh JWT — 30 дней. Значения настраиваются через окружение.
- Подпись JWT — HS256 с обязательным `JWT_SECRET`; в production cookie работают по HTTPS.
- Защищённые бизнес-маршруты для мониторов в этой задаче не добавляются, но будет подготовлена зависимость FastAPI для проверки Bearer access JWT.
